Neues Projekt · thingy52-live

Alle Thingy:52-Sensoren live im Terminal, im Browser und auf dem Handy

Die Idee in einem Satz: Der Thingy bleibt auf seiner Werksfirmware und sendet alle Sensordaten per Bluetooth. Ein kleines Windows-Programm empfängt sie, zeigt sie im Terminal, spielt „Highway to Hell“ auf dem Thingy ab und streamt die Daten live an eine Web-Oberfläche. Eine Android-App zeigt dasselbe auf dem Handy und öffnet sich per NFC.

Kein Flashen, keine Debug-Probe nötig Alle Tools in Docker Nur Kommandozeile

Wie fliessen die Daten?

Der Thingy erlaubt eine BLE-Verbindung gleichzeitig. Es ist also entweder der PC oder das Handy verbunden. Ein NFC-Tap aufs Handy ist der Wechsel.

📲 So öffnet NFC unsere App

  1. Die Werksfirmware hat einen NFC-Tag. Normal zeigt er auf Nordics App (no.nordicsemi.android.nrfthingy).
  2. Fund in der Firmware (m_ble.c, nfc_init): Den Tag-Inhalt kann man per BLE überschreiben, über die Konfig-Charakteristik EF680109 (max. 247 Byte). Er bleibt im Flash gespeichert.
  3. thingy nfc schreibt einmalig eine NDEF-Nachricht mit einem Android Application Record (AAR) für unsere App, z. B. ch.eicher.thingylive.
  4. Danach öffnet ein Tap mit dem Handy unsere App, die sich direkt per BLE verbindet.

Rückweg: thingy nfc --reset stellt den Originalinhalt wieder her.

Bau und Projektstruktur (alles Docker, alles CLI)

thingy52-live/
├─ project            # CLI: build · run · web · song · nfc · apk
├─ docker/Dockerfile  # Go + Android SDK + Gradle
├─ bridge/            # Go: BLE → Terminal + HTTP/SSE
│  └─ web/            # Dashboard (eingebettet in die exe)
├─ android/           # Kotlin-App, Gradle
├─ shared/chorus.json # Lied-Noten (aus Blinky)
├─ GOAL.md · JOURNAL.md · RESUME.md
└─ .github/workflows/ # baut exe + apk als Release
  • Go mit tinygo.org/x/bluetooth nutzt die Windows-BLE-API direkt. Es wird für Windows cross-kompiliert, das Ergebnis ist eine einzige .exe ohne Installation.
  • WSL kann kein Bluetooth. Deshalb läuft die exe auf Windows und wird aus WSL gestartet, wie schon highway.exe.
  • Web-GUI: HTML/JS eingebettet in die exe, Live-Daten über Server-Sent-Events, Kurven mit Canvas.
  • Android: Kotlin, minSdk 26, Debug-APK per Gradle im Container. Installation per adb oder APK-Download aus dem GitHub-Release.

Risiken

  • Firmware-Stand unbekannt: Wenn auf dem Thingy keine Werksfirmware mehr ist, fehlen die BLE-Services. Dann braucht es eine SWD-Probe zum Zurückflashen.
  • Mikrofon-Pegel: Der ADPCM-Stream braucht viel Bandbreite. Läuft er parallel zu Motion bei hoher Rate, kann es ruckeln. Abhilfe: Motion-Rate senken.
  • Speaker-Lautstärke: Der „Frequency mode“ ist eher leise. Alternative: 8-kHz-PCM-Stream, das ist aufwändiger.
  • Android ohne Handy am PC: Ich kann die APK bauen, aber nicht selbst auf dem Handy testen. Das macht der User.
