SRS: Software Requirements Specification

Rückwärts aus dem Code abgeleitet (Reverse Engineering). „Soll“ heisst hier: so verhält sich der Code heute. Wo das ein Risiko ist, steht der Befund in den Lücken. Die Systemanforderungen REQ-nnn stehen in management/REQUIREMENTS.md.

1. Zweckbestimmung (ANGENOMMEN, OPEN-01)

Das Gerät ist ein handgehaltener Bewegungssensor. Es misst Lage und Drehrate der Hand, berechnet daraus eine Orientierung und überträgt sie per Bluetooth LE an eine Auswertesoftware (Bridge oder App). Das Gerät stellt keine Diagnose und trifft keine Therapieentscheidung. Einsatz: Bewegungsübungen (Reha, Training) unter Aufsicht einer Fachperson.

Sicherheitsklasse: C (gesetzt, siehe Risiko). Alle Anforderungen gelten deshalb als Klasse C.

2. Legende

  • Kennz.: CODE = aus dem Code abgeleitet · ANNAHME = der Code selbst nennt den Wert eine Annahme · ADR = Entscheid in adr/firmware/.
  • Verifikation: Name des Host-Unit-Tests (Unity) oder NOT RUN (nur auf Hardware prüfbar, keine Unit-Tests für Zephyr-Adapter).
  • Die Host-Tests habe ich in dieser Sitzung nicht ausgeführt. Das README der Firmware nennt 32/32 PASS; im Code stehen 69 RUN_TEST. Der Widerspruch ist offen (GAP-20).
